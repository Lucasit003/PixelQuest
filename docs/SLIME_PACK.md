# Forest Slime pack — art + wiring contract

Production sprite sheets for the slime rework, replacing the procedural
`drawSlime()` disc. Four mobs, approved on review sheets 2026-08-26:

| mob | sheet | native body | role |
| --- | --- | --- | --- |
| Moss Dollop | `assets/actors/slime_dollop.png` | 15×11 | the common slime |
| Splitcrown | `assets/actors/slime_splitcrown.png` | 17×12 | elite — **splits on death** |
| Lobeling | `assets/actors/slime_lobeling.png` | 10×8 | Splitcrown child (inherits the leaf) |
| Nubling | `assets/actors/slime_nubling.png` | 8×6 | Splitcrown child (inherits the mote) |

All four share one visual grammar: near-black blue-green outline, sediment
settled along the base, upper-left light with mint sparks, pale pupil-less
embedded eyes, and forest debris suspended in the body (a leaf, a twig or
pebble, one faint magical mote). No smiles, no gradients, no anti-aliasing.
The goblin (~31px on the combat canvas) stands a head taller than everything
here — that ordering is deliberate and approved.

## Sheet convention (goblin rules)

192×120 sheets, 32×24 cells, 6 columns, frames across, one animation per
row, bottom-centre anchor. Authored at WORLD resolution: register with
`scale: 1` and combat's ACTOR_SCALE draws them at the approved 2.23×.
Airborne lift is **baked into the hop/slam cells**, so every row plays as a
plain animation — no z choreography required.

| row | state | frames | fps | notes |
| --- | --- | --- | --- | --- |
| 0 | idle | 0–3 | 5 | breathing squash/stretch |
| 1 | walk (hop) | 6–11 | 10 | compress → launch → airborne → pancake → wobble |
| 2 | attack (slam) | 12–17 | 12, no loop | slimelings use a 4-frame bounce (12–15) |
| 3 | hurt | 18–20 | 12, no loop | sheared away from the hit, squinting; mirror by facing |
| 4 | down (death) | 24–28 | 8, no loop | Dollop/children collapse to a puddle; **Splitcrown's row IS the split** |

Innards (debris, clusters, eyes) are rendered one frame of deformation behind
the outer wall — that lag is what sells the gelatinous mass. Keep it if
frames are ever regenerated.

## The split (Splitcrown death)

Down row: hit → lobes sag, saddle crease tears → the two masses pull apart
on a snapping goo strand with spray → burst → the two slimelings settled.
When the animation finishes, combat should spawn `slime_lobeling` and
`slime_nubling` at ±10 units with a small outward hop. Suggested numbers:
~30% / ~20% of Splitcrown's max HP, children never split again, XP split
60/20/20.

## Wiring (pending)

The sprite-catalog system these register into is still in flight on the
actor/combat side, so the sheets ship unwired. Drop-in registrations:

```js
registerActorSprite('slime_dollop', {
  sheet: 'assets/actors/slime_dollop.png',
  frameWidth: 32, frameHeight: 24, columns: 6,
  anchorX: 16, anchorY: 24, logicalHeight: 11, scale: 1, shadowRadius: 7,
  animations: {
    idle:   { frames: [0, 1, 2, 3], fps: 5 },
    walk:   { frames: [6, 7, 8, 9, 10, 11], fps: 10 },
    attack: { frames: [12, 13, 14, 15, 16, 17], fps: 12, loop: false },
    hurt:   { frames: [18, 19, 20], fps: 12, loop: false },
    down:   { frames: [24, 25, 26, 27, 28], fps: 8, loop: false },
  },
});
// slime_splitcrown: same block, logicalHeight 12, shadowRadius 8
// slime_lobeling:   logicalHeight 8, shadowRadius 5, walk fps 12,
//                   attack frames [12,13,14,15]
// slime_nubling:    logicalHeight 6, shadowRadius 4, walk fps 12,
//                   attack frames [12,13,14,15]
```

Frames were generated by re-rendering deformed contours through the shared
grammar engine (never by scaling pixels); the generators live with the
session tooling, and this document is the durable contract.
